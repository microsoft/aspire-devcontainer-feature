
# Aspire

This repo builds, tests and publishes a language-neutral devcontainer feature that installs the Aspire CLI and provides shared VS Code extensions and port-forwarding settings. Aspire manages the bundled .NET components it needs; a separately installed .NET SDK is not required by this feature.

Language-specific SDKs and editor tooling belong in the consuming devcontainer configuration or template preset. Starting with feature version 3, C# Dev Kit is no longer installed automatically; C# presets can explicitly add `ms-dotnettools.csdevkit`.

See the [feature documentation](src/aspire/README.md) for usage and the `installCli` option.

## Development

The feature README is generated from `src/aspire/devcontainer-feature.json` and `src/aspire/NOTES.md`. Update those sources, then run:

```sh
devcontainer features generate-docs --project-folder ./src --namespace microsoft/aspire-devcontainer-feature --github-owner microsoft --github-repo aspire-devcontainer-feature
```

Run the metadata checks and container scenarios with Node.js, the [Dev Container CLI](https://github.com/devcontainers/cli), and Docker:

```sh
node test/aspire/metadata.test.js
devcontainer features test -f aspire --skip-autogenerated --skip-duplicated .
```

The scenarios run with and without the Aspire CLI on a base image without a separately installed .NET SDK. The existing CI matrix also runs the default feature test against Debian, Ubuntu, and the devcontainers Ubuntu base image.

To test an unpublished candidate in a consuming devcontainer, copy `src/aspire` into `features/aspire` beside that configuration's `devcontainer.json`. Replace the published Aspire feature reference with `"./features/aspire": {}` and rebuild the container. Do not keep both the published and local references. Keep this local copy and reference out of the consumer's release changes.

Pull requests run the metadata/schema validation and container tests. The release workflow reuses both workflows for its exact commit and publishes automatically on `main` only after both succeed. Container-test failures are not allowed to pass silently. Configure these PR checks as required in the repository's branch protection or ruleset to also block merging on failure.

Publish the new major version before migrating consumers from `:2` to `:3`; existing `:2` consumers retain the previous C# customization.
